# 자불리스탄 맵 리워크 지시서 — "공중 발판 미로"에서 "데드 셀식 암반 굴착 지형"으로

> Codex에게: 이 문서는 `Nimrod` 프로젝트 14단계 자불리스탄 연속 월드(`data/world/zabulistan/`)의 **지형 구조와 지형 렌더링**을 다시 만드는 지시서다.
> 게임 시스템(능력, 사망 귀환, 저장 정책, 청크 스트리밍, 괴수 수치, 보스, HUD, 스토리)은 **바꾸지 않는다.** 바꾸는 것은 "땅이 어떻게 생겼고 어떻게 그려지는가"뿐이다.
> 지금까지의 규칙(손설계 ASCII, 난수·시드 생성 금지, 640×360 타일, 32px 타일, 64×36 청크, 10지역 5×2 배치)은 유지한다.

---

## 0. 한 문장 목표

**"허공에 3~4칸짜리 발판이 떠 있는 맵"을 "두꺼운 암반·건축물 덩어리 속을 파낸 방·복도·수직 갱도로 이루어진 맵"으로 바꾼다.**
빈 공간이 기본이고 발판을 얹는 방식(현재)이 아니라, **꽉 찬 암반이 기본이고 플레이어가 다닐 공간을 파내는 방식**으로 설계를 뒤집는다.

## 1. 현재 상태 진단 (실측)

`world_v2.json`의 `navigation` 640×360 = 230,400칸을 세었다.

| 글리프 | 의미 | 칸 수 | 비율 |
| --- | --- | --- | --- |
| `.` | 빈 공간 | 197,697 | **85.81%** |
| `=` | 단방향 발판 | 29,191 | 12.67% |
| `W` | 벽(매달리기 가능) | 2,488 | 1.08% |
| `#` | 고체 암반 | 1,024 | **0.44%** |

단방향 발판 `=`의 가로 길이 분포: 2칸 671개, **3칸 2,376개, 4칸 3,151개**, 5칸 532개, 6칸 이상 763개. 즉 **맵 전체가 3~4칸짜리 공중 발판 약 7,600개로 이루어져 있다.**

실제 화면 한 장(x 0~39, y 72~94)이 이렇다:

====......===...===.............===.....
........................................

..====............======...====......===
........................................

===........====.======...====...........

이것이 첫 번째 스크린샷의 문제 원인이다:

1. **천장·벽·바닥이 없다.** 화면에 "방"이라는 경계가 없어서 어디가 길이고 어디가 벽인지 읽히지 않는다.
2. **모든 발판이 공중에 떠 있다.** 벽에 박혀 있거나 사슬에 매달려 있거나 기둥에 받쳐진 것이 하나도 없다.
3. **배경 그림이 화면 85%를 차지한다.** 게임 공간과 배경이 분리되지 않고, 플레이어·적이 배경 위에 떠 보인다.
4. **고체 덩어리의 내부가 없다.** `#`가 0.44%라서 "두꺼운 땅"을 그릴 기회 자체가 없다.
5. 유일한 세로 구조물이 1칸 폭 `W` 기둥이라 "벽"이 아니라 "막대"로 보인다.

`docs/stage14_rework_report.md` 마지막 표에서도 "데드 셀식 지형의 시각적 완성도 ×(보완 필요)", "두꺼운 지반과 건축 구조로 동선을 감싸는 추가 수작업이 필요"라고 이미 스스로 인정했다. 이번 작업이 그 보완이다.

## 2. 데드 셀 맵의 해부 — 반드시 재현해야 할 12가지 원칙

레퍼런스 이미지 2(밝은 성 내부, 주황 나무 선반·사슬·천장 가시)와 이미지 3(어두운 지하 감옥, 검은 암반 덩어리 사이 수직 갱도)에서 관찰한 것을 규칙으로 옮긴다.

### 원칙 1. 화면의 40~65%는 고체다 (네거티브 스페이스 설계)
데드 셀의 어떤 화면을 캡처해도 화면의 절반 가까이가 검거나 어두운 **고체 덩어리**다. 플레이어가 다니는 공간은 그 덩어리를 "파낸" 모양이다. 이미지 3에서 화면 좌우 1/4씩과 상단 띠, 하단 좌우 블록이 전부 고체다. 이미지 2에서도 왼쪽 1/5이 보라색 암반 덩어리이고, 가운데 아래로 기둥이 떨어진다.
→ **모든 1280×720 화면 창(약 40×22타일)에서 고체 비율 ≥ 35%** (예외는 §7의 하늘 잔도·산 능선 외부 구간만 ≥ 20%).

### 원칙 2. 고체 덩어리의 "속"은 거의 단색으로 어둡게 칠한다
데드 셀 지형은 **가장자리 1~2칸만 디테일(벽돌, 바위 질감, 이끼, 금테)** 이 있고, 그보다 안쪽은 지역 색을 아주 어둡게 한 **거의 평평한 채움색**이다. 이미지 3의 검은 덩어리, 이미지 2의 짙은 보라 덩어리가 그것이다. 이 "어두운 속 + 밝은 테두리" 대비가 길과 벽을 한눈에 구분하게 해 주는 핵심이다.
→ 현재처럼 모든 고체 칸에 같은 밝은 돌 텍스처를 반복하면 안 된다(§6).

### 원칙 3. 모든 공간에는 바닥·천장·벽이 있고, 한 화면이 하나의 "방"처럼 읽힌다
플레이어가 서 있는 곳 위에는 반드시 천장이 화면 안에 보이고, 좌우 어딘가에는 벽이 보인다. 열린 공간(하늘이 보이는 곳)도 최소한 바닥과 한쪽 절벽 벽은 있다.

### 원칙 4. 발판은 절대 떠 있지 않다 — 박혀 있거나, 걸려 있거나, 받쳐져 있다
이미지 2의 주황 나무 선반은 전부 **왼쪽이나 오른쪽 벽에 박혀** 있고 아래에 까치발(브래킷)이 있다. 오른쪽 선반은 **사슬이 위에서 매달고** 있다. 이미지 3의 판자 발판도 사슬에 매달려 있다.
→ 모든 단방향 발판 `=` 줄은 (a) 한쪽 끝이 고체에 붙어 있거나, (b) 위쪽 고체에서 사슬 장식이 내려오거나, (c) 아래 고체에서 기둥 장식이 올라와야 한다. 셋 다 아니면 검증 실패.

### 원칙 5. 주 바닥은 두꺼운 고체이고, 단방향 발판은 보조 수단이다
데드 셀에서 걸어 다니는 대부분의 면은 고체 바닥이다. 단방향 발판은 (a) 수직 갱도를 오르는 사다리 역할, (b) 넓은 방의 2층 선반, (c) 구멍 위 다리로만 쓴다.
→ `=`는 전체 칸의 **2~4%** 로 줄인다(현재 12.67%).

### 원칙 6. 구조는 "방 + 복도 + 수직 갱도"의 조합이다
- **복도**: 가로로 긴, 천장 낮은 통로. 이동과 소규모 전투.
- **방(홀)**: 넓고 높은 공간. 전투·보물·랜드마크.
- **수직 갱도(샤프트)**: 폭 좁고 아주 높은 통로. 벽 양쪽에 번갈아 박힌 발판, 사슬, 이미지 3처럼 떨어지는 구간.
- **구덩이/낙하구**: 바닥에 뚫린 구멍으로 아래 층으로 떨어지는 지름길.
이 네 가지를 이어 붙이고, 그 사이는 전부 고체로 채운다.

### 원칙 7. 실루엣이 불규칙하다
고체 가장자리는 자로 그은 직선이 아니다. 천장에서 내려오는 종유석형 돌출부, 바닥에서 솟은 계단형 턱, 벽에서 튀어나온 바위 혹(오버행), 이미지 2 가운데처럼 바닥 아래로 내려가는 기둥이 있다. 2~3칸 단위로 가장자리가 들쭉날쭉해야 한다.

### 원칙 8. 방 안에는 "뒷벽"이 있고, 먼 배경은 구멍으로만 보인다
이미지 2는 방 안쪽에 벽돌 벽·그림 액자·석상이 있는 **뒷벽 레이어**가 있다. 먼 풍경은 거의 보이지 않는다. 이미지 3도 방 안은 어두운 벽돌 뒷벽이다.
→ 실내 공간 뒤에는 지역 건축 재질의 뒷벽을 깔고, 먼 패럴랙스 배경은 **외부로 뚫린 구역(창, 절벽 바깥, 갱도 입구)** 에서만 보이게 한다.

### 원칙 9. 위험물과 소품이 지형에 붙어 있다
천장 가시(이미지 2 위쪽), 바닥 가시, 촛불·통·상자·거미줄·사슬이 고체 면에 붙어서 크기 비교 기준이 된다. 소품은 반드시 바닥 위에 서 있거나 천장/벽에 매달린다.

### 원칙 10. 조명은 국소적이다
전체가 고르게 밝지 않다. 촛불·화로·창문 근처만 밝고, 덩어리 속과 구석은 어둡다. 지역마다 주조색이 있다(이미지 2 주황·보라, 이미지 3 청록).

### 원칙 11. 전경 실루엣이 화면을 감싼다
화면 가장자리에 플레이어보다 앞에 그려지는 어두운 덩어리(기둥, 사슬, 뿌리)가 가끔 걸쳐서 깊이감을 준다. 과하면 안 된다(한 화면 0~2개).

### 원칙 12. 같은 그림이 반복되어 보이지 않는다
방 템플릿은 여러 종류를 만들고, 같은 템플릿을 쓰더라도 가장자리 실루엣·소품·뒷벽 재질을 바꾼다. (현재의 "24×14 창 동일 지형 0건" 검사는 유지한다.)

## 4. 지형 문법

### 4.1 글리프 확장

`data/world/zabulistan/source/glyphs.json`과 `maze.ascii`, `tools/world/build_world.py`, `scripts/world/world_chunk.gd`, `tools/world/validate_world.py`가 함께 이해하도록 확장한다. 기존 글리프 의미는 바꾸지 않는다.

| 글리프 | 충돌 | 의미 | 렌더링 |
| --- | --- | --- | --- |
| `#` | 고체 | 암반/건축 덩어리 | 깊이별 자동 타일(§6.1) |
| `W` | 고체 | 매달리기 가능 벽면 | `#`과 같되 벽면 표시(긁힌 자국, 손잡이 홈) |
| `=` | 단방향 | 나무/돌 선반 | 지지 구조 자동 부착(§6.4) |
| `.` | 없음 | **실내 공간** (뒷벽 있음) | 뒷벽 레이어(§6.2) |
| `:` | 없음 | **외부 공간** (하늘/먼 배경 보임) | 뒷벽 없음, 패럴랙스 노출 — 신규 |
| `^` | 고체+피해 | 가시. 붙은 면 방향 자동 판정 | 지역별 가시 — 신규 |
| `~` | 없음 | 얕은 물/늪 물 (감속, 시각 효과만) | 반투명 수면 — 신규, 선택 |
| `F` | 고체(시야 전 상태) | 가짜 벽. 광질 시야(F)로 드러나면 통과 | `#`과 똑같이 그리고 시야 중 윤곽만 — 신규 |

- `:`와 `.`는 물리적으로 완전히 동일(빈 공간)하다. `world_manager.gd`의 `tile_at`, 시야선(`reveal_near`), 도달성 검사 모두 `:`를 `.`처럼 취급하도록 바꾼다.
- `^`는 서 있을 수 없는 고체로 취급하고 접촉 시 기존 함정 피해 처리(`stage5_hazard.gd` / `cedar_hazard.gd` 방식 재사용)를 한다. 도달성 검사에서 `^` 위는 착지 불가.
- `F`는 현재 `secret: true` 시야 게이트를 지형으로 표현한 것이다. 기존 시야 게이트 엔티티와 1:1 연결하거나, 게이트 엔티티를 유지하고 `F`는 순수 그림용으로만 써도 된다. 둘 중 단순한 쪽을 택하고 보고서에 적는다.

### 4.2 기본값을 뒤집는다: "전부 고체에서 파낸다"

현재 `maze.ascii`(80×45 판, 판마다 8×8 글리프)는 빈 공간 위에 발판 글리프를 배치하는 구조다. 이번에는 다음으로 바꾼다.

1. 각 지역(128×180칸)을 **처음에 전부 `#`로 채운다.**
2. **방 템플릿**(손으로 그린 ASCII 조각, §4.3)을 **명시적 좌표**로 찍어 파낸다.
3. 방과 방을 **복도·갱도 템플릿**으로 잇는다(역시 명시적 좌표).
4. 가장자리 다듬기 패스: 손으로 그린 "실루엣 스탬프"(종유석, 턱, 오버행, 기둥 돌출 등 3~8칸짜리 조각)를 명시적 좌표에 찍는다.
5. 소품·랜드마크·엔티티를 앵커 좌표에 둔다.

**난수·시드는 여전히 쓰지 않는다.** 모든 좌표는 `source/layout_<region>.json`(신규)에 사람이 적은 값이다. 컴파일러는 펼치기·검증·RLE·청크 분할만 한다. 원하면 80×45 판 형식을 버리고 지역별 레이아웃 JSON + 템플릿 디렉터리로 바꿔도 된다. 단 최종 출력(`world.ascii` 640×360, `chunks/*.json`, `world_v2.json` 형식)은 그대로 유지해 런타임 코드 변경을 최소화한다.

권장 소스 구조:

```
data/world/zabulistan/source/
  glyphs.json                 # 글리프 정의(확장)
  rooms/                      # 방·복도·갱도 템플릿. 파일 하나 = ASCII 조각 하나
    hall_iwan_48x22.txt
    corridor_low_40x5.txt
    shaft_qanat_8x60.txt
    ...
  stamps/                     # 실루엣 스탬프 (가장자리 다듬기용 작은 조각)
  layout_landing.json         # 지역별: 어떤 템플릿을 어디(x,y)에 찍는지, 좌우반전 여부
  layout_forest.json
  ...
  region_design.json          # 기존 유지 + 지역별 재질/소품/조명 키 추가
```

템플릿 ASCII에서 쓸 추가 표기(컴파일 후에는 사라짐):
- `?` = "덮어쓰지 않음"(바탕 유지). 템플릿을 겹쳐 찍을 때 사용.
- `P` = 소품 앵커, `L` = 랜드마크 앵커, `E` = 적 앵커, `G` = 게이트 앵커, `C` = 사슬 시작점. 컴파일러가 해당 칸을 `.`로 바꾸고 좌표를 엔티티/장식 목록에 넣는다. 이렇게 하면 `build_world.py`의 하드코딩 좌표(`enemy_points`, `landmark_points` 등)를 지역 레이아웃 기준으로 옮길 수 있다.

### 4.3 방 템플릿 라이브러리 (최소 구성)

각 지역은 아래 종류에서 **지역 테마에 맞게 변형한 템플릿**을 쓴다. 지역당 서로 다른 템플릿 최소 12개, 전 지역 합계 최소 80개(같은 모양을 지역 간 공유하더라도 실루엣 스탬프·재질로 차별화).

| 코드 | 종류 | 크기(칸, 내부) | 구성 |
| --- | --- | --- | --- |
| H1 | 대형 홀 | 48×22 | 평평한 주 바닥, 양쪽 벽에 박힌 2층 선반, 천장 돌출 1~2개, 랜드마크 앵커 |
| H2 | 계단형 홀 | 40×18 | 바닥이 2~3칸씩 계단처럼 오르내림. 단방향 발판 없음 |
| H3 | 구덩이 홀 | 40×20 | 가운데 낙하구(폭 5) + 그 옆 기둥(이미지 2 구조) |
| C1 | 좁은 복도 | 24~60×5 | 문·능력벽 설치 위치 |
| C2 | 전투 복도 | 30~80×8 | 바닥 턱 1~2칸, 천장 돌출 |
| C3 | 기기 틈 | 6~16×2 | 기기 잠금 |

| R1 | 보물 벽감 | 8×6 | 숨은 방, 기기 틈이나 가짜 벽 뒤 |

### 4.4 연결 규칙

- 한 지역 안에 **주 경로 1개 + 순환 고리 2~3개 + 막다른 보물 가지 3~5개**.
- 수직 이동은 갱도(S1~S4)로, 수평 이동은 복도(C1~C2)로. 방은 그 교차점.
- 지역의 세로 180칸(8화면 높이)을 활용해 **각 지역은 최소 4개 층**으로 나눈다. 층 사이 지반 4~10칸.
- 능력 잠금은 지형 모양으로도 읽히게 만든다:
  - 질주 → 가시 바닥 위 10~13칸 틈
  - 이중 점프 → 5~7칸 높은 턱
  - 벽의 발톱/벽 차오르기 → S3 갱도
  - 틈새 기기 → C3 높이 2칸 틈
  - 광질 시야 → `F` 가짜 벽
  - 천륜 빛 투척 → 틈 건너편 스위치
  기존 게이트 엔티티(`gate_<region>_<ability>`)는 그대로 두되, **그 게이트가 놓이는 자리의 지형을 위 모양으로** 만든다. 게이트는 반드시 높이 5칸 복도(C1)에 놓아 56×160px 벽이 통로를 완전히 막게 한다.
- 단방향 문(`door_<region>`, 오른쪽에서만 열림)은 C1 복도에 두고, 문 오른쪽에서 왼쪽으로 돌아오는 순환 고리가 실제로 존재해야 한다.

### 4.5 금지 규칙 (검증기가 실패시킬 것)

1. 떠 있는 `=` (한쪽 끝 고체 접촉·위 사슬 앵커·아래 기둥 앵커 중 하나도 없음)
2. 4방향 모두 빈 공간에 둘러싸인 고체 덩어리 중 면적 < 12칸인 것 (떠 있는 작은 돌). 예외: 사슬 앵커가 위에 있는 매달린 발판 블록
3. 두께 1칸짜리 고체 벽/바닥/천장 (`W` 기둥 1칸 폭 포함). 최소 2칸
4. 플레이어가 서 있을 수 있는 칸 위 4칸 이내에 고체가 있어 낀 상태가 되는 곳 (기기 틈 제외)
5. 40×22 창 중 고체 비율 < 35% (외부 예외 지역 < 20%)
6. 전체 `=` 비율 > 4%
7. 연속으로 30칸 이상 바닥 없이 빈 공간만 있는 열(낙하 갱도 S4로 표시된 곳 제외)

## 6. 렌더링 사양

현재 `world_chunk.gd`의 `build_rows()`는 고체 칸마다 `material = 6종 중 하나`, `edge = 4종 중 하나(위가 비었나/오른쪽/아래/그 외)`만 고른다. 이것을 바꾼다.

### 6.1 깊이 기반 자동 타일 (가장 중요)

고체 칸마다 **가장 가까운 빈 칸까지의 맨해튼 거리 `depth`**(0/1/2+ 3단계로 상한)를 구한다. 용량을 늘리지 않도록 **청크 JSON에 저장하지 말고**, 청크를 만들 때 런타임에 `world.tile_at()`(이웃 청크 2칸 포함)으로 계산한다. 상한이 2라서 칸당 최대 24칸 조회로 끝난다. 생성 단계 예산(step < 25ms)을 넘으면 그때만 컴파일 단계 저장으로 바꾸고, 저장할 때도 RLE로 한다.

| depth | 레이어 | 그림 |
| --- | --- | --- |
| 0 (빈 칸에 맞닿음) | 테두리(crust) | 4방향 인접 마스크 16종 + 안쪽 모서리 4종. 지역 재질 디테일 100% |
| 1 | 전이(transition) | 테두리 재질을 60% 어둡게, 균열·벽돌 이음새만 |
| ≥2 | 채움(fill) | **지역 팔레트 색을 명도 15~22%까지 낮춘 거의 단색**, 대비 5% 이하의 큰 무늬(64~128px 주기). 데드 셀의 검은/짙은 보라 덩어리에 해당 |

- 위쪽이 빈 테두리 칸(바닥의 윗면)에는 **위로 4~8px 튀어나오는 테두리 장식 스트립**(눈, 이끼, 풀, 금박 띠, 소금 결정 등 지역별)을 별도 레이어로 그린다. 충돌에는 영향 없음.
- 아래쪽이 빈 테두리 칸(천장 아랫면)에는 뿌리·고드름·거미줄·종유석 등 **아래로 늘어지는 장식**을 일정 비율(약 1/4칸)로 붙인다. 위치는 좌표 해시가 아니라 `(x*7 + y*13) % N` 같은 **결정적 수식**으로 고른다(난수 금지 규칙 유지).
- 테두리 마스크 16종 × 지역 재질 변형 최소 3종. 기존 `terrain.webp`(6재질×4방향)를 잘라 재사용해도 되지만, 부족한 마스크(좌상/우상 모서리, 1칸 돌출 등)는 스크립트로 합성하거나 새로 그린다.
- TileMapLayer를 2장으로 나눈다: `terrain_fill`(z=-4, depth≥1) / `terrain_crust`(z=-3, depth 0 + 스트립). 충돌 생성은 지금처럼 사각형 병합을 유지한다.

### 6.2 뒷벽 레이어 (`.` 실내 공간)

- `.` 칸 뒤에 지역 건축 재질 **뒷벽 TileMapLayer**(z=-8, 랜드마크 -7보다 뒤)를 깐다. 64×64 또는 128×128 반복 타일, 지역당 2~3종을 결정적 수식으로 섞는다.
- 뒷벽은 고체 가장자리에서 2칸 이내가 점점 어두워지는 **주변 차폐(AO) 그라데이션**을 갖는다(고체 테두리 마스크로 오버레이 1장 추가). 이것이 데드 셀 실내의 입체감을 만든다.
- 뒷벽 밝기는 고체 테두리보다 30~40% 낮게. 길(빈 공간)과 벽(고체)과 뒷벽 세 단계 명도가 분명히 구분되어야 한다: **테두리 > 뒷벽 > 채움**.

### 6.3 외부 공간 (`:`)

- `:` 칸에는 뒷벽이 없고 기존 지역 배경 3장(`background_0~2.webp`, 패럴랙스 0.12/0.30/0.58)이 보인다.
- `:`와 `.`의 경계에는 창틀·동굴 입구·무너진 벽 테두리 장식을 붙인다.
- 지역 배경은 화면의 **최대 30%** 에서만 보이게 레이아웃을 짠다(외부 예외 지역은 최대 60%).

### 6.4 단방향 발판 `=`의 지지 구조 자동 부착

컴파일 단계에서 각 `=` 줄을 판정해 장식을 붙인다:
- 왼/오른쪽 끝이 고체에 닿음 → 벽에 박힌 들보 끝 + 아래 대각선 까치발
- 위쪽 고체까지 수직 거리 ≤ 20칸 → 양 끝에서 사슬 2줄
- 아래쪽 고체까지 ≤ 6칸 → 받침 기둥
- 셋 다 아님 → **검증 실패**(§4.5-1)
발판 재질은 지역별(삼나무 들보, 석판 코벨, 밧줄 판자 잔도, 수정판 등).

### 6.5 소품과 랜드마크

- 기존 지역당 랜드마크 8개(`art_v2.json` 아틀라스)는 **홀(H1~H3, R2, R3)의 뒷벽에 박는다.** 3~4칸짜리 공중 발판 위에 세우지 않는다. 앵커는 홀 바닥 기준 `L` 표기.
- 바닥 소품: 화로, 항아리, 상자, 융단, 촛대, 무너진 기둥 조각. 천장 소품: 사슬, 등잔, 깃발, 뿌리. 벽 소품: 횃불, 부조판, 창살.
- 기존 공유 소품/광원(`npc_light_pool.webp`)을 우선 재사용하고, 새 그림이 필요하면 아트 예산(§8.4) 안에서 만든다.

### 6.6 조명

- 지역마다 `CanvasModulate`(또는 지금처럼 화면 전체 색 오버레이)로 기본 어둠을 깐다. 예: 명도 55~70%.
- 화로·횃불·창 위치에 가산 합성 광원 스프라이트(기존 `npc_light_pool` 재사용, 원형/원뿔 변형)를 둔다. 한 화면 2~5개.
- 외부 `:`에서 실내로 들어오는 경계에 빛줄기(god ray) 스프라이트 1장.
- 성능: 실시간 그림자 금지. 광원은 스프라이트 가산 합성만.

### 6.7 전경 레이어

- 플레이어 앞(z=+5)에 어두운 실루엣(기둥, 사슬 다발, 뿌리, 아치 기둥)을 **한 화면 0~2개**. 알파 0.85, 거의 검정. 전투 판독을 가리지 않게 화면 가장자리 20% 안쪽에만.
- 위치는 레이아웃 JSON에 손으로 적는다.

## 7. 자불리스탄 지역별 디자인 바이블

자불리스탄은 『샤나메』의 영웅 로스탐의 고향이고, 시무르그가 잘(Zāl)을 키운 산, 자하크가 사슬에 묶인 다마반드 산, 카나트(지하 수로), 바드기르(풍탑), 이완(아치형 대전), 사이프러스, 포도 정원, 흙벽돌·청록 타일·바위 부조의 세계다. 현재 첫 스크린샷은 모든 곳이 **회색 눈 덮인 돌** 하나로 통일되어 있어 지역 정체성이 사라졌다. 아래 표대로 지역마다 구조 문법·재질·색을 다르게 한다.

공통: 고체 채움색 = 해당 지역 팔레트를 명도 15~22%로. 테두리 = 팔레트 그대로~+20% 명도. 뒷벽 = 테두리보다 30~40% 어둡게.

### 7.1 착륙 절벽 (landing) `#65788c` — "계단식 착륙 잔교"
- **구조 문법**: 거대한 절벽면에 판 **가로 회랑**이 층층이 쌓인 형태. 지역 위쪽 1/3은 외부 `:` 비율 높음(바다·하늘), 아래로 갈수록 실내. 착륙 방(R4)은 맨 위 왼쪽.
- **고체 비율 목표**: 40~50%.
- **재질**: 바닷바람에 깎인 청회색 사암 + 흙벽돌 보강. 테두리 스트립 = 소금 서리/옅은 눈.
- **발판**: 절벽에서 튀어나온 나무 잔교, 밧줄로 매달린 판자.
- **뒷벽**: 흙벽돌, 갈대 엮은 차양.
- **소품**: 밧줄 더미, 정박 말뚝, 등잔, 깨진 항아리.
- **대표 방**: 계단식 잔교 홀(H2) — 바다 쪽으로 열린 외부면.

### 7.2 검은 숲 (forest) `#25463e` — "사이프러스 뿌리 회랑"
- **구조**: 거대한 사이프러스 뿌리와 흙이 고체를 이룬다. 복도가 뿌리 사이로 구불구불(가장자리 실루엣을 둥글고 불규칙하게). 거목의 **속이 빈 줄기 = 수직 갱도**(S1).
- **고체 비율**: 50~60%.
- **재질**: 검녹색 흙 + 뒤엉킨 뿌리. 테두리 = 이끼·풀. 천장 아래로 늘어진 잔뿌리.
- **발판**: 뿌리 가지가 벽에서 뻗어 나온 형태(`=`에 뿌리 지지 장식).
- **뒷벽**: 나무껍질, 뿌리 망.
- **소품**: 버섯, 반딧불, 사냥꾼의 덫(장식), 이끼 낀 석상.

### 7.3 황록 늪 (marsh) `#5a6630` — "카나트 침수 성소"
- **구조**: 카나트는 원래 "지표에서 일정 간격으로 판 **수직 우물**들이 아래의 **완만한 지하 수로**로 이어진 것"이다. 이것을 그대로 지형화한다: **위에서 내려오는 폭 5~6칸 수직 우물(S4/S1) 여러 개 + 아래의 길고 낮은 수로 복도(C2, 바닥에 `~`)**. 수로 끝에 침수된 성소 홀.
- **고체 비율**: 55~65%.
- **재질**: 젖은 황록 흙벽돌, 회반죽 수로벽. 테두리 = 이끼·물때. 수면 반사.
- **발판**: 수로 위 석판 다리, 우물 벽의 발 디딤 홈.
- **소품**: 물항아리, 도르래, 갈대, 잠긴 기둥.

### 7.4 무광 갱도 (mine) `#233c58` — "풍탑 갱도"
- **구조**: 바드기르(풍탑)의 **세로 환기 갱도** + 광산 수평갱. **수직성이 가장 강한 지역**: 높이 60~120칸 갱도 2~3개, 그 사이 수평 갱.
- **고체 비율**: 55~65%.
- **재질**: 검푸른 암반, 나무 갱목(천장과 벽을 받치는 들보 장식을 복도 10칸마다).
- **발판**: 갱목 비계, 사슬에 매달린 승강판(이미지 3 구조).
- **뒷벽**: 갱목 판자, 노출 암석. 거의 어두움. 등잔 몇 개만.
- **소품**: 광차, 곡괭이, 등잔, 바람에 흔들리는 천.

### 7.5 폐허 요새 (fortress) `#65504a` — "이완과 왕조 부조"
- **구조**: 바위 절벽을 파서 만든 왕조의 무덤·궁전(낙셰 로스탐의 십자형 암굴묘 이미지). **거대한 아치형 이완 홀**(H1, 위쪽 천장을 반원 아치 실루엣으로) + 성벽 위 흉벽 통로 + 보스 방(잊힌 이완의 수호자).
- **고체 비율**: 45~55%.
- **재질**: 붉은 갈색 사암, 다듬은 석재 블록(테두리에 벽돌 이음새). 테두리 스트립 = 무너진 돌 부스러기.
- **발판**: 석재 코벨(벽에서 튀어나온 돌 받침), 부러진 들보.
- **뒷벽**: 왕과 영웅의 바위 부조, 반쯤 무너진 아치, 깃발.
- **소품**: 무너진 기둥머리(황소 머리 기둥), 화로, 갑옷 잔해.

### 7.6 은신 마을 (village) `#665b4d` — "메라브 포도 정원"
- **구조**: 안전 지역(괴수 0). 계단식 정원 테라스 + 흙벽돌 집들 사이 골목. 외부 `:`와 실내 `.`가 섞여 있다. 수직 이동은 계단형 바닥(H2)과 나무 발코니.
- **고체 비율**: 40~50%.
- **재질**: 따뜻한 베이지 흙벽돌, 청록 타일 띠. 테두리 = 포도 덩굴·풀.
- **발판**: 나무 발코니, 포도 시렁(덩굴이 감긴 격자).
- **소품**: 포도 덩굴, 석류 나무, 융단, 물레, 화덕, 등불.
- 빛은 가장 따뜻하고 밝게.

### 7.7 산 능선 (ridge) `#7390a2` — "절벽 수도원"
- **구조**: 외부 예외 지역. 눈 덮인 능선 외부(X1)와 절벽에 판 수도원 승방(작은 방 R1/R2 연속). 바람 부는 바깥 → 좁은 문 → 따뜻한 승방의 리듬.
- **고체 비율**: 30~45% (외부 창 ≥ 20%).
- **재질**: 청회색 화강암 + 흰 회벽. 테두리 = 두꺼운 눈. 천장 아래 고드름.
- **발판**: 절벽에 박힌 나무 들보, 돌계단.
- **소품**: 기도 깃발, 종, 화로, 경전 함.
- **현재 첫 스크린샷의 눈 덮인 돌 질감은 이 지역에만 쓴다.**

### 7.8 하늘 잔도 (skywalk) `#41435f` — "시무르그 둥지"
- **구조**: 외부 예외 지역. "잔도"는 절벽에 구멍을 뚫고 나무를 박아 만든 길이다. 그러니 **거대한 수직 절벽 벽(두께 10칸 이상) + 그 벽에 박힌 판자 길 + 아래로 깊은 허공**. 여기서만 `=`가 많아도 되지만 **반드시 절벽에 박혀 있어야 한다.** 꼭대기에 시무르그 둥지(거대한 나뭇가지 둥지 홀, 보스: 하늘 잔도의 수호자).
- **고체 비율**: 25~40% (외부 창 ≥ 20%).
- **재질**: 남보라 절벽암. 테두리 = 깃털·마른 가지.
- **발판**: 판자 잔도 + 쇠말뚝 + 난간 밧줄.
- **소품**: 거대 깃털, 둥지 가지, 바람에 날리는 천 조각.

### 7.9 라오차흐 심층 (deep) `#533e66` — "다마반드 봉인 제단"
- **구조**: 다마반드 산 깊은 곳에 사슬로 묶인 존재(자하크 모티프)의 봉인. **아래로 깊이 내려가는 낙하 갱도(S4) 연쇄**, 바닥에 거대한 원형 제단 홀. 사슬이 모든 갱도를 가로지른다.
- **고체 비율**: 60~70% (가장 답답하고 어둡게).
- **재질**: 보라 흑요석질 암반, 사슬 박힌 벽. 테두리 = 보라 결정 맥.
- **발판**: 사슬에 매달린 철판, 봉인 석판.
- **소품**: 거대한 사슬, 봉인 부적판, 꺼질 듯한 보라 불꽃.

### 7.10 수정 협곡 (crystal) `#664677` — "라오차흐 결정 성소"
- **구조**: 좁고 깊은 **협곡**(양 벽이 두껍고 사이가 6~14칸, 높이 100칸 이상)에 결정 기둥이 튀어나와 발판 역할. 협곡 바닥에 결정 성소(보스: 결정 봉인의 수호자).
- **고체 비율**: 50~60%.
- **재질**: 자홍·보라 결정이 박힌 암반. 테두리 = 빛나는 결정 돌기(위로 솟음).
- **발판**: 벽에서 사선으로 자란 결정판(`=`에 결정 지지 장식).
- **소품**: 결정 군집(약한 가산 광원), 순례자의 촛대.

### 7.11 지역 경계

- 지역 사이에는 두께 8칸 이상의 암반 띠를 두고, 연결 관문(X2)을 기존 `connections` 수만큼(가로 이웃 1~2곳, 세로 이웃 1곳) 뚫는다.
- 경계 ±30칸(960px)에서 배경을 섞는 기존 처리는 유지하고, 관문 템플릿 안에서는 양쪽 재질이 반반 섞인 전환 테두리를 쓴다.

## 8. 파이프라인·코드 변경 목록

### 8.1 `tools/world/build_world.py`
- 지역별 `layout_<region>.json` + `rooms/` + `stamps/`를 읽어 "전부 `#` → 템플릿 파내기 → 스탬프 → 앵커 추출" 순서로 640×360 `world.ascii`를 만든다.
- 고체 `depth`는 저장하지 않는다(§6.1, 런타임 계산).
- `=` 지지 구조 판정 결과(벽 박힘/사슬/기둥)를 청크 `decor` 목록으로 저장한다. 항목은 `[종류번호, x, y]` 정수 배열로 저장하고 키 이름이 반복되는 객체를 쓰지 않는다(§12.3).
- 하드코딩된 `enemy_points`, `landmark_points`, 생명 조각·결정·게이트 좌표를 레이아웃의 앵커(`E`, `L`, `P`, `G`)로 대체한다. 엔티티 개수·종류·UID 규칙(`enemy_<region>_<k>` 등)은 유지해 저장 호환과 기존 테스트를 지킨다.
- `support()`의 "가장 가까운 발판에 발 붙이기"는 유지하되, 이제 대부분 넓은 고체 바닥에 붙어야 한다. 적의 순찰 폭(`patrol: 96`)이 확보되도록 **적 앵커 아래 바닥은 최소 8칸 평지**.

### 8.2 `scripts/world/world_chunk.gd`
- `build_rows()`: `depth`에 따라 `terrain_fill` / `terrain_crust` 두 레이어에 칸을 놓고, 테두리는 16마스크로 타일을 고른다.
- `.` 칸에 뒷벽 레이어, `.`/`:` 경계에 창틀 장식.
- `^` 처리(고체 + 피해 Area2D, 인접 가시는 사각형 병합).
- `decor` 목록(사슬, 까치발, 기둥, 스트립, 늘어짐 장식, 전경 실루엣) 생성. 지금의 "타일 4행/장식 1개/개체 1개씩" 단계 생성 방식을 유지해 프레임 P95 < 50ms, step < 25ms를 지킨다.

### 8.3 `scripts/world/world_manager.gd`
- `tile_at`, `reveal_near`의 고체 판정에 `^`(고체), `F`(시야 전엔 고체), `:`(빈 공간) 반영.
- `terrain_set()`을 지역별 crust/fill/backwall TileSet 세 개로 확장, `prewarm_art()`에 포함.
- 지역별 `CanvasModulate` 색 전환(경계 960px 혼합은 기존 배경 혼합과 동일 방식).

### 8.4 아트
- 지역당: 테두리 16마스크×3변형, 채움 1~2종, 뒷벽 2~3종, 테두리 스트립 1종, 늘어짐 장식 3~4종, `=` 재질 1종, 지지 장식(까치발/사슬/기둥) 지역 공용 + 색 변조.
- 기존 `terrain.webp`·`background_*.webp`·`landmarks.webp`를 최대한 재사용·재가공한다.
- **용량 규칙은 §12를 따른다.** 새 지형 레이어를 추가하더라도 `assets/world/zabulistan_v2` 전체는 현재 5.79 MiB보다 **줄어야** 한다.

### 9.2 화면 검사 (GL 캡처)

`tests/stage14_stream_capture.gd`를 확장해 **10개 지역 × 3장(대표 홀, 갱도, 복도) = 30장**을 캡처하고 `docs/stage15_map_review/`에 저장한다. 각 캡처에 대해 보고서에 적는다:
1. 화면 고체 비율(%)
2. 천장이 보이는가 / 좌우 벽이 보이는가
3. 떠 있어 보이는 요소가 있는가
4. 테두리 > 뒷벽 > 채움 명도 순서가 지켜지는가 (각 영역 평균 명도 수치)
5. 지역을 이름 없이 그림만 보고 구분할 수 있는가 (지역 간 주조색 차이)

그리고 **레퍼런스 이미지 2·3과 나란히 놓은 비교 이미지**를 지역당 1장 만든다.

### 12.2 지형 아트 — "색은 런타임에, 그림은 회색조 1벌로"

데드 셀식 지형은 레이어가 늘어나지만 대부분 **단색에 가깝거나 반복**이라 용량을 거의 쓰지 않게 만들 수 있다.

1. **채움(fill)은 이미지 0바이트.** depth ≥ 2 칸은 텍스처를 쓰지 않는다. 모든 지역 공용 64×64 회색조 저대비 노이즈 타일 1장(≤ 4 KB)에 지역색을 `modulate`로 곱한다. 또는 아예 단색 사각형으로 그린다.
2. **테두리(crust)는 회색조 공용 아틀라스 + 지역 팔레트.** 16마스크×3변형×재질 계열 몇 종을 **회색조(L) 1벌**로 그리고, 지역 색은 `modulate` 또는 2색 그라디언트 매핑 셰이더(그림자색/밝은색 2개 uniform)로 입힌다. 지역 10개가 아틀라스를 공유하므로 지역별 `terrain.webp`가 필요 없어진다. 재질 계열이 정말 달라야 하는 지역(흙벽돌/뿌리/결정/눈 화강암 등)만 계열별 1장. **목표: 지형 아틀라스 합계 ≤ 300 KB.**
3. **뒷벽**: 128×128 반복 타일, 회색조 + 팔레트 방식. 지역당 2~3종이지만 계열이 같으면 공유. **합계 ≤ 400 KB.** 뒷벽은 어둡게 그려지므로 64×64로 그려 2배 확대 표시해도 된다 — 먼저 64×64로 시도하고 캡처 비교에서 티가 나면 128×128.
4. **AO(주변 차폐) 그라데이션, 테두리 스트립, 늘어짐 장식, 사슬·까치발·기둥**: 모든 지역 공용 소형 아틀라스 1장(≤ 256×256, ≤ 60 KB)에 회색조로 넣고 색 변조.
5. **가산 광원**: 새 이미지 없이 기존 `npc_light_pool.webp`를 크기·색 변조로 재사용.
6. 셰이더는 `gl_compatibility` 렌더러(현재 프로젝트 설정)에서 동작하는 단순 `canvas_item` 셰이더만 쓴다.

### 12.3 랜드마크·배경

1. **랜드마크 아틀라스(현재 지역당 0.3~0.4 MiB, 합계 약 3.5 MiB)가 지역 아트 용량의 대부분이다.**
   - 랜드마크는 이제 홀 **뒷벽에 박히는 어두운 층**(§6.5)이므로 원본 해상도가 필요 없다. 현재 셀 284px를 `game_scale` 1.11로 **확대 표시**하고 있다. 아틀라스를 0.75배(1024→768)로 줄이고 `game_scale`을 그만큼 키워 화면 크기를 유지한다. 뒷벽 밝기·AO가 덮이므로 캡처 비교로 확인한다. 예상 절감 약 40%.
   - 3×3 격자(셀 341px 중 그림 284px)의 빈 여백을 없애고, 알파 bbox 기준으로 빽빽하게 다시 패킹한다(여백 2px 유지).
   - 지역당 8개 중 실제로 홀 뒷벽에 들어가는 개수만 남긴다. 새 레이아웃에서 홀이 지역당 4~6개라면 남는 랜드마크는 `archive/`로 옮긴다(삭제 아님). "같은 랜드마크 재사용 금지" 규칙은 유지한다.
   - 알파 테두리가 거의 없는 그림은 RGB + 1비트 알파 또는 무손실 알파 + 손실 RGB(WebP `alpha_quality` 분리) 조합을 후보로 시험한다.
2. **배경 3장(1024×256, 4배 표시)** 은 이미 작다(지역당 0.2 MiB 내외). 새 레이아웃에서 외부 `:` 공간이 화면의 30% 이하로 줄어들므로, 가장 먼 층(`background_0`, 패럴랙스 0.12)은 512×128로 줄이고 8배 표시해도 되는지 캡처 비교로 확인한다.
3. **지역 간 배경 공유**: 같은 계열(예: 산 능선·하늘 잔도의 하늘층, 무광 갱도·라오차흐 심층의 암흑층)은 1장을 공유하고 색 변조로 구분한다.

### 12.4 맵 데이터

1. `world_v2.json`의 `navigation`(640자 × 360줄, 약 230 KB)은 청크 RLE와 **완전히 중복**이다. 런타임은 청크에서 `navigation`을 복원하거나, `navigation`을 줄 단위 RLE로 저장한다. 검증 도구가 원문 줄이 필요하면 `source/world.ascii`(빌드 입력, 실행 ZIP 제외)를 읽게 한다.
2. 새 지형은 고체가 대부분이라 RLE 효율이 훨씬 좋아진다. 청크 RLE를 `[["#",40],[".",24]]` 같은 중첩 배열 대신 **문자열 RLE**(`"40#24."`)로 바꾸면 JSON 구문 오버헤드가 사라진다. 런타임 파서 한 함수만 바꾸면 된다.
3. 엔티티·장식 목록은 키 반복 객체 대신 정수 배열(`[종류, x, y, 플래그]`)로. UID는 규칙(`enemy_<region>_<k>`)으로 런타임에 생성할 수 있으면 저장하지 않는다. 단, 세이브 호환을 위해 **생성 결과 UID 문자열은 지금과 똑같아야 한다.**
4. `art_quality.json`, `stage14_rework_placements.json` 같은 QA·보고용 JSON은 실행 ZIP에서 제외한다(QA ZIP에만).
5. 목표: `data/world` ≤ 0.40 MiB.

### 12.5 프로젝트 전체 (맵 작업 후 별도 단계)

맵만으로는 63 MiB에 도달할 수 없다(스프라이트가 44.8 MiB). 맵 작업이 승인된 뒤 아래를 순서대로, 각 항목마다 **측정 → 적용 → 품질 검사 → 실패 시 원복**으로 진행한다.

1. **표시 배율 감사 (가장 효과가 큼).** 모든 스프라이트 시트에 대해 게임 안에서 실제로 그려지는 최대 화면 크기를 측정한다(카메라 최대 줌, 스프라이트 `scale`, 노드 `scale` 모두 곱함). 시트 해상도가 최대 표시 크기보다 1.1배 이상 크면 **최대 표시 크기의 1.0배로 축소**한다. 이는 화면에서 보이는 결과가 사실상 같으므로 품질 기준을 화면 렌더 결과 기준으로 비교한다(원본 대비 비교가 아니라 "축소 전 시트로 그린 화면 vs 축소 후 시트로 그린 화면" GL 캡처 SSIM ≥ 0.93). 대상 우선순위: `gugalanna`(walk 3072×390 등), `kala_ushumgal`, 플레이어 클립, `castle_great_gate`, `hwanira/plaza`(3200×896).
2. **프레임 수 감사.** 각 클립의 재생 fps 대비 프레임 수를 검사한다. 인접 프레임 SSIM ≥ 0.985인 쌍은 병합하고 재생 시간을 보존한다(기존 `merge_world_idle_frames.py`, `stage13_merge_frames.py` 방식 재사용). 보스 클립(`phase_transition`, `collapse`, `death`처럼 한 번만 재생되는 것)은 12fps 상한을 검토한다.
3. **좌우 반전 중복 제거.** `turn` 클립이나 좌/우 별도 시트가 단순 반전 관계면 하나만 남기고 `flip_h`로 그린다.
4. **알파 트림 재확인.** 프레임별 투명 여백을 잘라 내고 프레임별 오프셋을 매니페스트에 기록(`trim_sprites.py` 재사용). 시트 셀이 가장 큰 프레임 기준으로 고정돼 있으면 빈 공간이 많다.
5. **큰 단일 이미지 분할 반복.** `plaza.webp`, `stars_tile.webp`, `mid_trunks_tile_2d.webp`, `mid_district_tile.webp`처럼 넓은 배경은 반복 가능한 구간을 찾아 타일 + 고유 장식 몇 개로 나눈다.
6. **Godot 가져오기 설정 확인.** 이 프로젝트는 소스 폴더 ZIP으로 배포되지만, 내보내기(.pck)를 할 경우 텍스처 `compress/mode`가 Lossless이면 WebP 이점이 사라진다. 큰 텍스처는 `compress/mode=1 (Lossy)` 또는 WebP 유지 설정으로 두고, 소스 ZIP에서는 `.godot/`·`.import` 캐시가 제외되는지 계속 검사한다(현재 제외됨, 회귀 방지).
7. **오디오는 건드리지 않는다**(이미 모노 48kbps, 효과 대비 손실 큼).

각 항목의 실제 절감량(B), 시험했지만 기준 미달로 버린 후보와 그 수치를 `docs/SIZE_REPORT_KO.md` 15단계 절에 표로 남긴다. "예상 절감"이 아니라 **적용 후 실측값**만 완료로 표시한다.

### 12.6 런타임 메모리·성능 (용량과 같이 지킬 것)

- 고체가 늘어나도 충돌은 지금처럼 **사각형 병합**을 유지한다. 추가로, 빈 칸에 닿지 않는 고체(depth ≥ 2)는 충돌 사각형 병합 대상에서 더 큰 사각형으로 합쳐지도록 해 `StaticBody2D` 수를 늘리지 않는다.
- 장식(사슬, 까치발, 스트립, 늘어짐)은 개별 `Sprite2D` 노드 대신 **장식 전용 TileMapLayer** 또는 청크당 `MultiMeshInstance2D` 1개로 그린다. 청크당 노드 수 ≤ 250.
- 회색조 공용 아틀라스 방식이면 VRAM에 올라가는 지형 텍스처가 지역 수와 무관해진다. `prewarm_art()`에서 지역별 TileSet을 10벌 만드는 대신 공용 TileSet 1~3벌 + 지역 색 uniform으로 바꾼다.
- 측정값 `STATIC_MEMORY_DELTA_BYTES`(현재 7,506,040)가 늘지 않아야 한다.
