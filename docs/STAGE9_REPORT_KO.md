# NIMROD 9단계 작업 보고

8단계 ZIP 가져오기 수정 버전(71a2adf)을 기반으로 수정했다. 실제 기존 시작 지점은 NimrodHome/Spawn_Start(x=330), 맨손이며 이를 유지했다. Godot 공식 4.3 GL Compatibility, 1280×720로 검사한다. 플레이어 HP180·도끼20/20/20/22·이동360·구르기780/0.48·선딜0.03/무적0.25/후딜0.20·콤보 리셋0.8·히트스톱0.05는 유지했다.

## 스토리 구현

Story와 Cutscene autoload를 추가했다. 상태는 기존 GameState.run_flags에 저장하며 사망/F5로 이야기·무기·스킬·축복·대화 방문을 초기화한다. 문법 예약어 is와 Object.set 충돌을 피해서 API는 Story.is_flag(), set_flag(), stage()로 제공한다. 단계표·NPC 존재 조건·전체 원문 대사는 STAGE9_STORY_FLOW_KO.md에 있다.

variants는 우선순위 첫 일치 항목을 선택한다. 완료한 variant의 repeat가 비면 E를 숨기며 낮은 우선순위 항목으로 돌아가지 않는다. 그룹 화자 누구에게나 E로 같은 공유 플래그를 사용한다. 기존 단일 first/repeat 구조는 유지한다. unlock_skill/start_cutscene/time_skip 이벤트를 추가했고 식사·귀환·축복을 기존 상호작용과 연결했다.

밤은 kala_first_defeat && !time_skipped로 계산한다. 모든 레벨 CanvasModulate(0.58,0.64,0.88), 빛 웅덩이는 색 역보정이다. NPC/소품 presence와 식탁 almost/full/prep는 로드 때와 스토리 플래그 변경 때 갱신한다. 별장 낮 하인과 요리사 대화는 없다. 칼라 최초 처치 플래그는 사망 연출과 첫 처치 대사 이후 켜며 다시 싸울 때 첫 대사는 반복하지 않는다.

## 식사·귀환 컷신

Cutscene은 데이터의 lock/unlock/walk_to/play_clip/face/문/spawn/despawn/dialogue/fade/wait/flag/teleport/무기 숨김 단계를 실행한다. AI·위험·타이머를 정지하고 컷신이 직접 움직이는 배우만 계속 처리한다. 대화 중에는 해당 배우까지 정지한다. 취소·레벨 이동에서도 입력·무기 표시·알파·자리 높이·NPC 처리 모드와 pause를 복구한다. 아직 끝나지 않은 타이머·이동·페이드도 해제하며 취소된 식사는 다시 시도할 수 있다.

자리: 니므롯1220(우), 아야1480(좌), 샤마쉬1620(좌), 바닥620, 앉기 y오프셋−18px. 실제 의자·식탁과 머리/손 높이를 캡처해 조정했다. 식탁은 x950,y530,게임900×90px, 의자 x1120,y470,520×150px이다. 플레이어 자리로 걷기0.4초, 시작 후0.8초에 위 문 열림, 문 열림0.6초, 아야 이동1.3초/샤마쉬1.5초를 데이터에 둔다. NPC들은 같은 문을 순서대로 통과한다. 식사 중 실제 무기 소유 상태는 유지하고 맨손 앉기만 표시하며 종료 후 복원한다.

시간 경과는 1.5초 페이드아웃→1.0초 유지→time_skipped→CastleF1 Spawn_Wake x760→crouch_exit→1.5초 페이드인이다. 암전 문구는 비어 있다. 엔키두아는 report_done 이후 루갈성1층 x1120에 나타나고 집에서는 사라진다. 기상 후 엔키두아→부모님 대화 전까지 뒷문 메시지는 ‘아직 이곳을 떠날 수 없다’. 식사 종료 임무 토스트 ‘삼나무 숲을 조사한다’는1.8초, data/story.json objective_toast로 끌 수 있다.

## 입력·아누르의 빛

R=skill_light, 재시작은 F5로 변경했다. 실제 Godot 기능키 코드와 기존 F1~F5 매핑이 2만큼 달랐던 것도 수정했다(F5=4194336). F6/F7은 ENABLE_DEBUG_TELEPORT가 켜졌을 때 누적 단계 이동과 현재 레벨 재로드, 1/2 순간이동 유지, 대화/컷신 중 무시한다.

아누르의 빛은 요청의 제안값을 채택했다: 900px/s,700px,56×28,관통2,36×공격력 배율,쿨다운5초(공속 무관),경직0.2초,발사 앞24px/서 있는 충돌 높이124px의60%(발 위74.4px),0.12초 이동50%. normal/점프에만 사용하며 공격·구르기·피격·수그리기·사슬 끌림·대화·컷신 중 차단한다. 고체와의 충돌은 중심선만 검사하지 않고 사각형 swept shape로 판정한다. 갑피 괴수의 정면 가드는 유지하고 훔바바의20% 감쇄는 적용하지 않는다. 획득 뒤에만 HP 아래 R슬롯과 쿨다운 채움/도움말을 표시한다.

## 훔바바

HP1350, 몸270×310, 슈퍼아머/넉백20%, 정면 기본 공격×0.8/등 뒤 정상/빛 정상. 방향 전환0.60/2페이즈0.45초, 턴의3번째 프레임에 뒤집는다. 물기24(선딜0.90/active0.20/도약200/후딜1.0/220×140), 할퀴기14×3(선딜0.60/0.25×3/후딜1.1/260×150), 화염2×16(선딜0.80/1.6초/후딜1.3/사거리600/45도/쿨다운6), 꼬리12(선딜0.30/active0.15/후딜0.6/뒤240×80)를 데이터에 둔다. 등 뒤 꼬리 견제 확률50%, 이후 실제 TURN으로 들어가며 공격/후딜 중 방향 고정이다.

HP675 이하1.8초 포효 동안 무적(시간은 계속 흐름), 이후 모든 공격 시간×0.87, 할퀴기4회=56, 불18틱=36/좌우±30도 훑기, 별도2페이즈 시트 대신(1.18,0.86,0.8)+불씨 FX이다. 18틱을 유지하려고 2페이즈 화염의 기본 방사 길이는1.8초로 정하고 ×0.87을 적용한다. 불은 첫 틱 포함 경직/피격 유예 없이 처리하며 구르기 무적은 유지한다. 같은 패턴 연속 선택을 막는다.

보스 선택: humbaba_defeated→없음, anur_blessing_done→훔바바, 나머지→칼라-우쉬움갈. 기존 x≥450 전투 시작/HP바/입구 잠금을 재사용하며 훔바바 처치 후 문이 열린다. 이번 범위는 처치 플래그까지이며 이후 이야기는 추가하지 않았다.

## 최종 배포 검증

공식 Godot4.3에서 새 ZIP을 별도 폴더에 풀어 임포트1개+스크립트 파싱59개+회귀 테스트48개, 총108/108 통과했다. 엔진 ERROR/SCRIPT ERROR/WARNING은0건이다. ZIP에 포함된 데이터와 이미지로 에셋·알파·도달성·괴수 프레임·접지·표시 크기 검증7단계를 모두 통과했다. 검사 내역은 [STAGE9_HEADLESS_RESULTS.json](STAGE9_HEADLESS_RESULTS.json)에 있다. 별도 Python 회귀 검사2개도 통과했다.

마지막 문서 재패킹 때 런타임 파일·코드·데이터·테스트·도구가 검증된 압축 해제본과 해시가 동일함을 확인한다. Godot 네이티브 ZIPReader/프로젝트 가져오기와 CRC도 다시 검사한다. 공유용 ZIP은 archive·캐시·개발 원본과 오래된 캡처를 제외하며 project.godot과 모든 필요한 폴더 항목을 포함한다.
