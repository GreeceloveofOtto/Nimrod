# Codex 지시 — 15단계 착륙 절벽 검토 결과와 다음 작업

착륙 절벽 검토본(`Nimrod_stage15_landing_review_2026-10-16.zip`)을 확인했다.

**승인하는 것**: 암반을 기본으로 두고 공간을 파내는 방향, 테두리·전이·내부·뒷벽 4단 렌더링, 회색조 공용 아틀라스, 발판 지지 장식, 문자열 RLE, navigation 중복 제거, 검증기 구조, 성능·메모리 결과. 이 방향은 그대로 유지한다.

**아직 승인하지 않는 것**: 착륙 절벽의 **배치**. 아래 1장의 문제를 고쳐야 한다. 그리고 지시서가 갱신되었다(2장). 나머지 9지역을 만들기 전에 1장과 2장을 착륙 절벽에 먼저 적용한다.

첨부한 새 지시서 `ZABULISTAN_MAP_REWORK_SPEC_KO.md`로 `docs/STAGE15_MAP_REWORK_SPEC_KO.md`를 **교체**하고, 이후 모든 판단은 새 지시서를 따른다. 새 지시서와 이 프롬프트가 다르면 이 프롬프트가 우선한다.

데드 셀 레퍼런스 이미지 2장(밝은 성 내부 / 어두운 지하 갱도)을 이번에 함께 첨부한다. 지난번에는 첨부가 빠졌다. 이번에는 비교 이미지를 만든다.

## 1. 착륙 절벽 배치에서 고칠 것

검토본의 `world_v2.json` 청크를 펼쳐 착륙 절벽 128×180타일을 그려 보면, 지표 수치(고체 49.75%, `=` 2.01%, 떠 있는 발판 0)는 맞지만 구조가 **아파트 단면도 같은 격자**다. 데드 셀 맵이 아니다.

### 1.1 문제

1. **똑같은 층이 9번 반복된다.** 층 바닥이 y = 12, 32, 52, …, 172로 정확히 20칸 간격이고, 거의 모든 층이 지역 폭 전체를 가로지르는 비슷한 높이(8~9칸)의 복도다. 24×14 동일 창 검사는 통과하지만 눈으로 보면 같은 띠가 9번 쌓여 있다.
2. **똑같은 수직 우물 2개가 지역 전체 높이를 관통한다.** x=38~45와 x=82~89에 폭 8칸짜리 우물이 위에서 아래까지 이어지고, 3칸 간격 선반이 사다리처럼 끝까지 반복된다. 수직 이동이 지루하고 단조롭다.
3. **큰 방이 없다.** 높이 18~26칸 대형 홀(H1), 계단형 홀(H2), 구덩이 홀(H3)이 보이지 않는다. 모든 실내 공간의 높이가 비슷하다.
4. **게이트 8개가 x=74 한 열에 층마다 하나씩 세로로 줄지어 있다.**
5. **외부 공간 `:`이 316칸(약 1.4%)뿐이다.** 착륙 절벽은 위쪽 1/3이 하늘로 열린 절벽면이어야 한다(지시서 §7.1).
6. **바다가 들어갔다.** 바다 파노라마 배경, `salt`·`sea_iwan`·`sea_gate`·`salt_crypt`·`pier` 같은 바다 테마 템플릿 이름과 소금 서리 스트립이 있다. 새 지시서 §7.0에 따르면 바다(보루카사 해)는 흐와니라에 있고 **자불리스탄에는 없다.**

### 1.2 고치는 방법

- **층 격자를 깬다.**
  - 층 높이를 서로 다르게 한다(5, 8~9, 12~16, 18~26칸을 섞는다).
  - 지역 폭 전체를 가로지르는 복도는 2개 이하로 줄인다. 나머지는 지역 폭의 30~60% 길이 복도가 엇갈리게 이어지도록 한다.
  - 큰 홀이 두세 층 높이를 한 번에 차지하게 한다.
- **수직 이동을 다양하게 한다.** 갱도 종류를 섞는다: 사다리 갱도(S1), 이중점프 갱도(S2), 벽점프 갱도(S3), 낙하 갱도(S4). 각 갱도의 길이는 30~80칸으로 서로 다르게 하고, 위치도 엇갈리게 둔다. 지역 높이 절반(90칸)을 넘게 이어지는 갱도는 S4 낙하 지름길 1개만 허용한다.
- **방 템플릿을 섞는다.** 착륙 절벽에 최소 H1 1개, H2 1개, H3 1개, R4(착륙 방) 1개, R5(귀환 잔교) 1개, X1(외부 절벽면) 2개, R2(축제 터) 1~2개를 넣는다.
- **위쪽 1/3을 외부 절벽면으로 만든다.**
  - 하늘과 먼 산맥, 검은 숲 골짜기가 보이는 `:` 공간에 절벽에 박힌 잔교를 둔다.
  - 지역 전체에서 `:` 비율은 10~20%로 한다. 외부 공간이 있는 40×22 창도 고체 20% 이상 규칙은 지킨다.
- **바다를 모두 걷어낸다.**
  - `background_1`(바다 파노라마)을 **산맥과 검은 숲 골짜기**로 다시 만든다.
  - `zabulistan_landing_sea.md` 프롬프트와 `pack_landing_sea.py`는 `archive/`로 옮긴다.
  - 바다·소금 이름이 들어간 템플릿 파일 이름과 장식(소금 서리 → 서리/옅은 눈)을 바꾼다.
- **게이트를 흩는다.** 게이트는 지역 곳곳의 곁가지 입구에 둔다. 게이트끼리 x좌표가 12칸 이상 떨어져야 하고, 같은 열에 3개 이상 겹치면 안 된다. 게이트 배치 규칙은 새 지시서 §13.3을 따른다(능력 잠금은 주 경로에 두지 않는다).

### 1.3 이 문제를 잡는 검증 추가 (`validate_world.py`)

| 검사 | 기준 |
| --- | --- |
| 층 반복 | 바닥 높이 y값 간격이 같은 층이 3개 이상 연속되면 실패 |
| 전폭 복도 | 지역 폭의 70% 이상 끊김 없이 이어진 수평 통로는 지역당 2개 이하 |
| 공간 높이 분포 | 지역마다 내부 높이 ≥ 16칸인 공간 2개 이상, ≤ 6칸인 공간 3개 이상 |
| 갱도 길이 | 연속 90칸을 넘는 수직 통로는 S4 1개만 |
| 게이트 열 | 같은 x(±3칸)에 게이트 3개 이상 금지 |
| 외부 비율 | 착륙 절벽·산 능선·하늘 잔도는 `:` 10% 이상 |
| 금지 테마 | 템플릿 이름·이미지 프롬프트·장식 키에 `sea`, `salt`, `바다`, `소금`, `시무르그`, `다마반드`, `수도원`, `기도` 사용 금지 |

## 2. 지시서 갱신분 (새 지시서에서 바뀐 곳)

지난 검토본은 이전 지시서를 기준으로 만들었다. 새 지시서에서 바뀐 곳은 아래와 같다. 자세한 내용은 해당 절을 읽고 그대로 구현한다.

1. **§0 (머리말)**: 이번 범위에 능력 초기화, 수집품 교체, 지역 이름 수정이 추가되었다. 세계관 근거 문서 3종을 따른다.
2. **§7.0 세계관 기준 · §7.0.1 지역 이름·세트피스 변경표**: 자불리스탄은 숨어 살다 숙청된 비와라습 혈통의 행성이고, 라오차흐가 약하며, 산과 검은 숲으로 이루어져 있다. 다마반드·시무르그·바다·결정 지대·종교 의례는 쓰지 않는다. 지역 이름 4곳, 세트피스 8곳, 보스 표시 이름 2개, crystal 팔레트를 바꾼다.
3. **§7.1~7.10**: 지역별 바이블을 위 기준에 맞게 다시 썼다(우주마 착륙 잔교, 숙청의 요새·지워진 쌍흑사 부조, 봉화 망루, 버려진 우주마 마구간, 혈통의 지하 피난처, 잿빛 협곡·불탄 축제 터).
4. **§13 능력 초기화**:
   - 맵에서 얻는 능력 7개는 **사망하면 전부 사라진다.**
   - 능력은 지역마다 있는 **축제 터**(기존 altar 대체)에서 시도마다 다시 얻는다. 같은 능력을 주는 터가 최소 2곳 있다.
   - `requires` 체인은 제거한다.
   - 주 경로·보스·지역 입구·축제 터 1곳·귀환 잔교에는 능력 없이 갈 수 있어야 한다. 획득 순서는 2단까지만 허용하고, 어떤 상태에서도 갇히면 안 된다.
   - 착륙지에서 각 지역 입구까지 3분 이하로 갈 수 있어야 한다.
   - 기존 "131,072상태" 검사는 §13.3의 기준으로 바꾼다.
5. **§14 수집품 교체**:
   - 생명 조각은 **축제의 색끈**(`cord`)으로 바꾼다. 영구 수집품이고, 4개마다 최대 HP +10, 상한 200이다. 줍는 즉시 회복하던 기능은 없앤다.
   - 결정은 **축제의 불씨**(`ember`)로 바꾼다. 죽으면 0이 되고, 모아서 바치는 것 외에는 쓰임이 없다.
   - **귀환 잔교** 4곳을 둔다. 살아서 돌아오면 광장 화로에 불씨를 바치고, 바친 양은 영구 누적된다.
   - 스토리용 카운트 키를 기록한다(§14.4). 값에 따른 대사·이벤트는 이번에 만들지 않는다.
   - 세이브 스키마를 3으로 올린다(스키마 2의 `life_fragments`·`abilities`는 버리고 나머지는 옮긴다).
6. **§11 건드리지 말 것**: 진행 유지/소멸 규칙과 세이브 스키마는 이제 바뀌는 대상이다. 능력 **수치**·키는 그대로 둔다.
7. **§9.1 완료 기준**: 능력 관련 검사 행이 바뀌었다.

## 3. 작업 순서

1. 새 지시서로 `docs/STAGE15_MAP_REWORK_SPEC_KO.md`를 교체한다.
2. 1.3의 검증을 추가하고 현재 착륙 절벽에 돌려 실패 목록을 남긴다(실패가 나오는 것이 정상이다).
3. §13·§14 시스템을 구현한다: 능력 초기화, 축제 터, 색끈, 불씨, 귀환 잔교, 스키마 3, 지도 아이콘, HUD 능력 아이콘, 테스트(§14.6).
4. §7.0.1 이름 변경을 10지역 데이터 전체에 반영한다. 이름·세트피스·보스 표시 이름만 바꾸고, 지형은 착륙 절벽만 바꾼다.
5. 착륙 절벽 배치를 1.2대로 다시 만든다. 바다 배경을 산맥·검은 숲 골짜기로 교체한다.
6. 착륙 절벽 캡처를 만든다: 홀, 갱도, 복도, 외부 절벽면, 축제 터, 귀환 잔교 6장. 그리고 레퍼런스 이미지 2·3과 나란히 놓은 비교 이미지 1장과, 128×180 전체를 글리프별 색으로 그린 **지역 배치도 1장**(검토본 대비 전후)을 만든다.
7. **여기서 한 번 더 멈추고 확인을 받는다.** 승인 후 나머지 9지역(지시서 §10의 4번 이후)을 진행한다.

## 4. 유지할 것

- 이번 검토본의 성능(P95 8.2ms, step 13.5ms, 노드 1655, 메모리 7,488,612B)보다 나빠지지 않는다.
- 실행 ZIP은 72.23MiB보다 커지지 않는다. 월드 아트·데이터 목표(§12)는 그대로다.
- 난수·시드 생성 금지, 손설계 템플릿과 명시 좌표 원칙.
- 기존 테스트 196개 전부 통과. 능력 영구 획득을 전제로 한 테스트는 의도를 §13 기준으로 바꿔서 고친다(삭제하지 말 것).
- 보고서는 `docs/STAGE15_MAP_REWORK_REPORT_KO.md`를 갱신하고, 1장의 문제 6개를 각각 어떻게 고쳤는지 표로 적는다.
